# Методика

Все формулы реализованы в `backend/app/analytics/` и `backend/app/demo/`; этот документ их пересказывает.

## Данные FACEIT
Провайдеры (`app/providers/`) возвращают «сырые» ответы в формате FACEIT Data API v4; единый нормализатор
(`app/faceit_normalize.py`) превращает их в доменные модели. Поэтому fixtures и живой API проходят один и тот же код.

## Rating 1.0
`(KPR/0.679 + 0.7·SPR/0.317 + RMK/1.277) / 2.7`, где RMK = Σ k²·(раунды с k убийствами)/раунды. В статистике FACEIT
количество раундов с одним убийством не дано и вычисляется как kills − 2·2k − 3·3k − 4·4k − 5·5k. В демках используется
точное число убийств в каждом раунде.

## Сильные и слабые стороны (FACEIT-статистика)
Для каждой метрики и каждого матча берётся разница «игрок − среднее остальных 9 игроков этого матча» (контроль контекста
матча: карта, длина, уровень лобби). Среднее разниц + bootstrap 95% CI (2000 повторов). Классы: сильная сторона — CI > 0
и эффект ≥ 0.25 SD лобби; зона роста — зеркально; иначе «в норме». Минимум 5 матчей. Для entry и клатчей — пуловые
доли игрока с интервалом Уилсона против пуловой доли лобби, минимум 15 попыток. Доверие: низкое < 20 матчей,
среднее < 60, высокое ≥ 60.

## Разбор демки
* Раунды: события `round_end` после последнего `round_announce_match_start`/`begin_new_match`; событие принадлежит
  раунду, если его тик между официальными концами предыдущего и текущего раундов (`round_officially_ended`).
* Команды A/B устойчивы к смене сторон: определяются по составу на первом раунде.
* ADR: урон по здоровью врагов с учётом остатка HP (`dmg_health` в CS2 может превышать оставшееся здоровье).
* KAST: убийство, ассист (в т.ч. флеш-ассист), выживание или разменянная смерть.
* Трейд: убийство врага, который убил тиммейта, в пределах 5 секунд.
* Клатч: команда сокращена до одного живого игрока при ≥ 1 живом сопернике; результат — победа команды в раунде.
* Экономика: суммарная стоимость снаряжения на конце freeze time; средняя на игрока ≥ $3900 — фулл-бай, ≥ $2000 — форс,
  ниже — эко; раунды 1 и 13 — пистолетные.
* Хайлайты: см. докстринг `app/demo/highlights.py` (база за мультикилл, бонусы за клатч, скорость, особые убийства,
  контекст раунда; порог 30).

## Матчмейкинг («скрытый пул»)
Гипотеза формулируется через проверяемые следствия; каждое — отдельный тест с методом, минимальным n и альтернативными
объяснениями. p-значения корректируются Бенджамини–Хохбергом (FDR 10%). «Аномалия» требует и q < 0.1, и практически
значимого эффекта (≥ 15 Elo разницы команд, |ρ| ≥ 0.1, ≥ 3 п.п. отклонения доли побед); иначе «слабый сигнал».
Итоговый вердикт касается только тестов, прямо связанных с гипотезой, и всегда сопровождается оговоркой, что
аномалия — не доказательство.

Валидация детектора (`tests/test_analytics.py`): на синтетике без скрытого пула тесты «соперники после серий» и
«результат после серий» не дают аномалии (3 seed × 200 матчей); при внедрённом эффекте (соперники скрыто сильнее после
серий побед) тест «результат после серий» его находит.
