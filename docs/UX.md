# Интерфейс: движение, состояния, сеть

Единые правила, по которым построен весь фронтенд. Каждое правило записано в одном месте кода, экраны его не
повторяют.

## Быстрый доступ
* **Одно поле** на главной и в разведке: ссылка на комнату запускает разведку, ник (или ссылка на профиль FACEIT)
  открывает игрока. Кнопка заранее показывает, что произойдёт: «Разведка» / «Открыть игрока».
* **Ctrl+V в любом месте** приложения (вне полей ввода) со ссылкой на комнату сразу запускает разведку.
* **Ctrl+K / ⌘K** — палитра: ссылка, ник, разделы, недавние разведки, игроки и демки.
* **«Профиль»** в навигации — свой FACEIT-профиль в один клик.

## Отчёт разведки
1. **Сводка** на первом экране:
   * шанс вашей команды по Elo и фаворит;
   * 3 главные угрозы соперников;
   * кто с кем играет;
   * карта: выбранная или сильные/слабые карты до выбора;
   * необычные профили.

   Каждый блок ведёт к своему подробному разделу.
2. **Липкая навигация по разделам:** Брифинг · Угрозы · Связки · Карты · Тактика · Стабильность.
3. **Пустые разделы свёрнуты в одну строку с причиной** (например, тактика без демок), но открываются одним
   кликом — ничего не скрыто насовсем.
4. **Отчёт, сделанный во время выбора карт,** следит за комнатой: когда карту выбрали, он перестраивается сам
   (тост «Карта выбрана: …»).
5. **«Карты» — пул карт вашего стака.** Вы, сохранённые тиммейты и те, с кем вы часто играете, отмечаются
   переключателями; рядом показано, как эти карты играют соперники. Тот же расчёт есть отдельной страницей «Стак»
   (`/stack?players=a,b`).

## Язык движения
*«Спокойная точность»*: анимация объясняет смену состояния и никогда не заставляет ждать.

| Токен (`app/styles/index.css`) | Значение | Где |
|---|---|---|
| `--dur-instant` 90 мс | отклик на нажатие | `pressable`: кнопки, чипы, ссылки навигации |
| `--dur-fast` 150 мс | наведение, поповеры, уход | Select, Tooltip, тосты |
| `--dur-base` 240 мс | появление контента, смена состояния | `animate-enter`, `animate-fade-in`, загруженные данные, страницы |
| `--dur-slow` 420 мс | морфинг, рисование галочки | карточка входа (`MorphHeight`), `SuccessCheck`, полоса прогресса |
| `--ease-arrive` | замедление при появлении | всё, что появляется |
| `--ease-leave` | быстрый уход | закрытие поповеров |
| `--ease-morph` | плавное «в обе стороны» | высота, прогресс |
| `--ease-confirm` | небольшой «перелёт» | только подтверждение (галочка) |

* Анимируются только `transform` и `opacity` (GPU). Таблицы и длинные списки не анимируются построчно; у
  разделов отчёта короткий каскад (`--i` × 45 мс, не больше 6 шагов).
* Страница появляется подъёмом на 6 px за 240 мс. У вкладок игрока шапка неподвижна, меняется только содержимое.
* Карточка входа одна на все фазы. Меняется её содержимое, высота перетекает, бренд остаётся на месте.
* `prefers-reduced-motion`: без перемещений, мерцания и «перелёта». Индикаторы активности (`.motion-essential`)
  медленно крутятся: они означают «ещё работаю».

## Загрузка
* **Скелетон повторяет структуру контента**: плитки KPI, графики со столбиками, таблицы со строками, шапка
  игрока. Базовые блоки лежат в `shared/ui/skeleton.tsx`, композиции страниц — рядом со страницами.
* **Без мерцания**: скелетон появляется, только если ответ идёт дольше 160 мс (`useDelayed`). Быстрый ответ
  показывает контент сразу.
* **`AsyncView`** — единый жизненный цикл запроса:
  * данные на экране всегда главнее: фоновое обновление и его сбой их не стирают;
  * пока нет данных — скелетон;
  * без сети и без кэша — состояние ожидания, а не бесконечный скелетон;
  * при ошибке — классифицированное сообщение с «Повторить».
* Смена выборки матчей оставляет прежние цифры на экране и показывает подсказку «Обновляем данные…».
* Код страниц грузится по требованию. Пока он загружается, текущая страница остаётся на месте, а под шапкой
  тонкая полоса. Графики (recharts) скачиваются только на страницах, где они есть.

## Долгие операции
`JobProgress` показывает шаги, которые сообщает сервер.
* **Разведка**: стадия `match → players → briefing` и настоящий процент из backend.
* **Демка**: настоящий процент отправки байтов, затем «очередь → разбор» без цифр — сервер их не знает.

Со страницы можно уйти. `JobWatcher` следит за задачами, запущенными в этой вкладке; задачи переживают
обновление страницы. О завершении он сообщает тостом с кнопкой «Открыть». «Готово» появляется только после
ответа сервера.

## Ошибки (`shared/api/errors.ts`)
API-клиент один раз классифицирует любой сбой, и все экраны показывают его одинаково:

| Вид | Как определяется | Что видит пользователь |
|---|---|---|
| `offline` | `navigator.onLine === false` | баннер «Нет подключения»; данные остаются, действия ждут |
| `unreachable` | запрос не дошёл / 502–504 без нашего JSON | баннер «Сервер не отвечает», авто-переподключение, «Проверить» |
| `faceit_unavailable` | ответ сервера с `source: "faceit"` | «FACEIT временно недоступен» — не путается с поломкой приложения |
| `rate_limited` | 429 (+ `Retry-After`) | время, когда можно повторить; кэш доступен |
| `unauthorized` | 401 | карточка входа с пояснением «Сессия истекла» |
| `not_found` | 404 | экран называет, что именно не найдено («Игрок … не найден»), и предлагает поиск |
| `timeout` | 180 с на чтение / 120 с на действие | «Ответ не пришёл вовремя» |
| `server` | 500 | «Ошибка на сервере» без трассировок |

Отмена запроса (уход со страницы) — это не ошибка: она не попадает ни в состояние экрана, ни в тосты.
Повторы: автоматически только один тихий повтор при `server`. 429, таймауты и недоступность не повторяются
сами, чтобы не долбить FACEIT.

## Уведомления (`shared/lib/notify.ts`, `app/providers/query-client.ts`)
* Тост подтверждает действие или сообщает о его провале. Сами действия описаны в `meta` мутаций:
  * `success` — текст подтверждения;
  * `errorContext` — префикс сообщения об ошибке;
  * `inlineError` — ошибка показывается рядом с формой, тоста нет.
* Загрузка, пустые данные и ошибки экрана показываются на месте, без тостов. Проблемы связи показывает баннер.
* Одинаковые проблемы склеиваются: у лимита, недоступности FACEIT и ошибок сервера постоянные id, поэтому
  десять запросов дают один тост.
* Длительность: успех — 3 с, проблема — 6 с, фоновая задача — 8 с с действием. Одновременно видно максимум 3.
  Позиция: справа внизу, на телефоне — внизу во всю ширину. Каждый тост можно закрыть.
* Фоновое обновление, которое сломалось при уже показанных данных, даёт один тост «Показаны последние
  загруженные данные».

## Кнопки и формы
* `Button loading`: вместо иконки спиннер, `aria-busy`, повторное нажатие заблокировано, ширина не прыгает.
* Удаление (демка, цель, привязка) — `ConfirmButton` в два шага, без модального окна. Подтверждение
  сбрасывается через 3,5 с, по Esc или при потере фокуса.
* В настройках кнопка «Сохранить» активна только при изменениях. Есть «Отменить изменения»; ошибка
  показывается рядом с кнопкой; «Сохранено» появляется только после ответа сервера.
* Вход: повторный клик по провайдеру не запускает второй вход. Если вернуться «назад» со страницы провайдера,
  карточка возвращается в исходное состояние.

## Проверка
`make e2e-ux` (`scripts/e2e_ux.cjs`) — браузерные сценарии против MOCK FACEIT:
* фазы входа;
* медленные, сломанные и отменённые запросы;
* фоновая разведка;
* загрузка демки с отменой и повтором;
* настройки (ожидание, двойной клик);
* офлайн, сервер недоступен, восстановление, истёкшая сессия;
* Slow 3G и Fast 3G — настоящее ограничение задержки и полосы через CDP, холодный кэш;
* reduced motion, ширина телефона.

Скриншоты состояний сохраняются в папку, переданную аргументом.
