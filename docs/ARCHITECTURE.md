# Архитектура

```
frontend/ (React 18 + TS, Vite, Tailwind v4, shadcn-style UI, TanStack Query, FSD)
  app/ pages/ widgets/ features/ entities/ shared/
backend/ (FastAPI, SQLAlchemy + SQLite, demoparser2, numpy/scipy)
  app/
    main.py, state.py        — сборка приложения, DI-контейнер (тесты собирают своё приложение)
    config.py, db.py         — настройки (.env), модели хранилища
    providers/               — FACEIT Data API клиент (+ fixtures только для тестов)
    auth/                    — сессии/CSRF/лимиты, Steam OpenID 2.0, FACEIT OAuth2+PKCE
    routes/                  — HTTP: auth, me, players, demos, scout(+predictions, feedback), coach, maps
    analytics/               — статистика игрока, инсайты, Elo, матчмейкинг (этап 1)
    scout/                   — Match Scout: features → strength / chemistry / risk → briefing → service
    tactical/                — извлечение позиций из демок, зоны, radar transforms, профили
    demo/                    — парсинг и анализ демок (этап 1, расширен позиционными срезами)
    predictions.py, coach.py — проверка прогнозов, коучинг
  tests/support/             — симулированный мир FACEIT и mock HTTP-сервер (только для тестов/E2E)
```

## Хранилище (SQLite, `DATA_DIR/app.db`)
`DATA_DIR` по умолчанию `backend/data`; лаунчер Windows — `%LOCALAPPDATA%\FaceitIntelligence\data`. Схема версионируется через
`PRAGMA user_version`: новые столбцы добавляются миграциями при старте, данные не пересоздаются. Задачи разведки, прерванные
перезапуском, помечаются ошибкой с предложением повторить.

| Таблица | Назначение |
|---|---|
| users, identities | внутренний аккаунт и *подтверждённые* внешние логины (provider, subject уникальны) |
| game_profiles | какой FACEIT-профиль принадлежит пользователю и как это установлено (FACEIT OAuth / Steam→FACEIT) |
| sessions, oauth_states | хэши токенов сессий, одноразовые state + PKCE verifier + привязка к браузеру |
| user_settings, analysis_log | предпочтения и история открытых анализов |
| player_snapshots | наблюдённые официальные значения Elo/уровня: новая строка только при изменении, иначе обновляется `confirmed_at`; привязанные игроки опрашиваются раз в `TRACKING_INTERVAL_MINUTES` (пауза при 429) |
| scout_reports | задачи разведки и готовые отчёты |
| predictions (+ prediction_outcomes) | неизменяемые предматчевые снимки (`before_update` запрещает изменения) и результаты |
| feedback | мнения пользователя о выводах — отдельно от фактов |
| tactical_samples | позиционные наблюдения из демок (позиции по фазам, дуэли, размены) |
| goals | цели коучинга с замороженным базовым уровнем |

Персональные данные минимальны: SteamID/FACEIT guid и ник; токены доступа FACEIT не сохраняются.

## Данные FACEIT и производительность
* Разведка одного матча: 1 запрос матча + 4 на игрока (профиль, lifetime-статистика, 30 последних матчей, история) ≈ 41
  запрос. Клиент ограничивает частоту (4 rps по умолчанию), объединяет одинаковые параллельные запросы, кэширует на диск
  (профили 10 мин, статистика 30 мин, завершённые матчи навсегда, идущий матч 20 с). Повторная разведка того же матча в
  течение 5 минут переиспользует отчёт.
* Разведка выполняется фоновой задачей (asyncio) с прогрессом; парсинг демок — в отдельном процессе.
* Пул карт стака (`app/scout/stack.py`, `GET /api/stack/maps?players=a,b`):
  * каждый игрок: старые матчи на карте сглаживаются к 50%, последние ~100 — к старым;
  * группа: среднее по игрокам, которое сдвигают матчи, сыгранные вместе (из истории);
  * мало опыта у кого-то — карта уходит в конец списка.
* Открытый отчёт, сделанный до выбора карты, опрашивает `GET /api/scout/{id}/live` (кэш 20 с) и перестраивается
  после выбора.
* Фоновые задачи (`app/tracking.py`): Elo привязанных игроков раз в `TRACKING_INTERVAL_MINUTES`, сверка прогнозов
  с итогами раз в `PREDICTION_CHECK_MINUTES`. При 429 обе пропускают запуск.
* Объединённый запрос выполняется отдельной задачей: если браузер ушёл со страницы и один из ожидающих отменён, запрос
  доводится до конца для остальных (раньше это могло оборвать разведку). Каждый запрос разведки ограничен 90 с.
* При 429 FACEIT клиент выдерживает паузу по `Retry-After`, до её конца отдаёт кэш или понятную ошибку со временем повтора.
* При недоступности API отдаются сохранённые данные с пометкой `stale` и временем, а не выдуманные значения.

## Тактическая разведка: как она точнеет
Каждая загруженная демка добавляет `tactical_samples`: позиции живых игроков через 12/28/50 с после freeze time (callout
из nav mesh игры и координаты), места всех дуэлей и размены. Профиль игрока (по SteamID) агрегирует все демки, где он
встречается. Уровни доказательности «недостаточно / предварительно / устойчивый паттерн» зависят от числа раундов и
доверительного интервала доли зоны. Нет демок — нет позиционных выводов.
