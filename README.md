# FACEIT Intelligence

Аналитика FACEIT / Counter-Strike 2: статистика игрока и тренды, лучшие и худшие матчи, сильные и
слабые стороны относительно лобби, разбор CS2-демок (раунды, KAST, ADR, openings, трейды, клатчи,
утилита, экономика), хайлайты с тиком для перехода в демке, исследовательский анализ матчмейкинга
(«скрытый пул») и исследовательские оценки Elo.

* **backend/** — Python 3.11+, FastAPI, demoparser2, numpy/scipy. Провайдер FACEIT Data API v4 + офлайн-fixtures.
* **frontend/** — React 18 + TypeScript, Vite, Tailwind CSS v4, компоненты в стиле shadcn/ui (Radix), Recharts,
  TanStack Query; структура Feature-Sliced Design (`app / pages / widgets / features / entities / shared`).
* **legacy/telegram-bot-go/** — старый Telegram-бот на Go, сохранён без изменений (см. «Аудит»).

## Быстрый старт

Нужны: Python ≥ 3.11 с [uv](https://docs.astral.sh/uv/), Node.js ≥ 20.

```bash
make install          # uv sync + npm install
make serve            # сборка UI и запуск API+UI на http://localhost:8000
```

Режим разработки (две консоли): `make backend` (:8000) и `make frontend` (:5173, прокси `/api` → :8000).

Без API-ключа приложение работает на локальных данных. Сразу доступны:

| Игрок | Источник | Что есть |
|---|---|---|
| `limelightttt` | **Реальный снимок** ответов FACEIT `/matches/{id}/stats` (10 матчей, ноябрь 2025) из старого бота | Статистика всех 10 игроков каждого матча. Нет Elo, времени матчей, Elo команд |
| `sim_player` | **Синтетика** в точном формате FACEIT API (`app/synthetic.py`, seed 7) | 150 матчей с Elo, временем, составами — только для демонстрации Elo/матчмейкинга |
| Демо `sample00mirage` | **Реальная CS2-демка** (Valve MM, de_mirage, 10 раундов) из тестов demoparser2, MIT | Предразобранный пример |

В UI источник данных всегда помечен бейджем («FACEIT API», «Реальный снимок», «Синтетика»), а
ограничения данных перечислены в заголовке игрока.

### Подключение FACEIT Data API

1. Создайте приложение на <https://developers.faceit.com> (App Studio) и получите **server-side API key**.
2. `cp backend/.env.example backend/.env` и укажите `FACEIT_API_KEY=...`.
3. Перезапустите backend: `/api/health` покажет `"provider": "faceit_api"`.

Клиент (`backend/app/providers/faceit_api.py`) использует `GET /players`, `/players/{id}/history` (пагинация по 100),
`/matches/{id}`, `/matches/{id}/stats`; ограничивает частоту запросов (по умолчанию 4 rps, `FACEIT_REQUESTS_PER_SECOND`),
повторяет запросы при 429 с учётом `Retry-After` и при 5xx, кеширует завершённые матчи на диск навсегда, профиль и
историю — на 5 минут. Ключ не логируется и не возвращается API. Официальный Elo фиксируется при каждом запросе
(`data/elo_snapshots/`), со временем из этого складывается реальная история Elo.

> В этой облачной сессии разработки ключа не было, а `open.faceit.com` был закрыт сетевой политикой окружения, поэтому
> живой API **не проверялся** на реальных ответах. Клиент покрыт тестами на mock-транспорте (пагинация, 429, 401/404, кеш),
> а нормализатор проверен на реальных сохранённых ответах `/matches/{id}/stats`.

### Демки

Скачайте демо на странице матча FACEIT и загрузите в разделе **Демки** (`.dem`, `.dem.gz`, `.dem.bz2`, `.dem.zst`,
до 1 ГБ — `MAX_DEMO_UPLOAD_MB`). Парсинг идёт в отдельном процессе; исходный файл удаляется после разбора,
хранится только `analysis.json`. Пример реальной демки: `make sample-demo` → `samples/test_demo_mirage.dem`.

Хайлайты содержат команду `demo_gototick <tick>`: откройте демку в CS2 (`playdemo ...`), вставьте команду в консоль —
окажетесь за 5 секунд до первого убийства момента.

## Методика

Подробно — [docs/METHODOLOGY.md](docs/METHODOLOGY.md). Коротко:

* **Rating 1.0** — опубликованная формула HLTV 1.0 (для FACEIT-статистики раунды с 1 убийством восстанавливаются из 2k–5k).
* **Сильные/слабые стороны** — парное сравнение с 9 другими игроками тех же матчей, bootstrap 95% CI, порог эффекта
  0.25 SD; для долей (entry, клатчи) — пуловые доли с интервалом Уилсона. Мало данных → явно «мало данных».
* **Матчмейкинг** — 8 тестов наблюдаемых следствий гипотезы «скрытого пула» (калибровка побед к ожиданию по Elo,
  runs-тест серий, сила соперников после серий, результат после серий vs ожидание, пати vs соло, баланс команд,
  карты, время суток), поправка Бенджамини–Хохберга, требование практической значимости эффекта, список альтернативных
  объяснений в каждом тесте. Никакого «Hidden Pool Score». Детектор проверен на синтетике: без эффекта не даёт
  аномалии (3 seed), с внедрённым эффектом — находит его.
* **Elo** — официальный Elo отделён от оценок: реконструкция назад по правилу Elo, Monte Carlo прогноз,
  «Elo по результатам» (перформанс-рейтинг 5v5) и «Elo по игре» (рейтинг vs уровень в лобби) с интервалами.

## Аудит исходного репозитория

Исходный код — Telegram-бот на Go (~850 строк): команды `/collect` и `/analyze`, OAuth-callback, приём webhook
`DEMO_READY`, прокси для скачивания демок через DNS-over-HTTPS.

* Сохранено: реальные ответы FACEIT в `cmd/data/limelightttt.json` (стали fixture-датасетом), список используемых
  эндпоинтов Data API.
* Ошибки старого анализа: `AnalyzeStoredMatches` искал `players` на верхнем уровне ответа (его там нет — игроки лежат в
  `rounds[0].teams[].players`) и суммировал статистику **первого попавшегося** игрока матча, а не запрошенного; win rate
  не считался. OAuth-токен передавался как Bearer в Data API; прокси подменял DNS и User-Agent для CDN — такой обход
  не переносился.
* Решение: архитектура бота не подходит для веб-продукта и парсинга демок (нет слоя данных, анализ внутри клиента API),
  поэтому новая система написана рядом, а бот перенесён в `legacy/telegram-bot-go/` без изменений (собирается
  `go build ./...`). Python выбран для backend из-за зрелых парсеров демок (demoparser2/awpy) и scipy.

## Ограничения и что не сделано

* Живой FACEIT API не проверен (нет ключа, хост закрыт в окружении разработки) — см. выше.
* Парсер проверен на **одной** реальной CS2-демке (Valve MM, 10 раундов, капитуляция). На демках FACEIT
  (рестарты, ножевой раунд, овертаймы) логика границ раундов покрыта, но на реальном файле FACEIT не проверялась.
  Ножевые раунды пока не исключаются отдельно.
* Пати определяется эвристикой (повторяющиеся тиммейты): Data API не отдаёт party id для матчмейкинга.
* «Опыт аккаунтов» (число матчей/возраст аккаунтов лобби) не анализируется — требует запроса профиля каждого игрока.
* Elo за отдельный матч в Data API нет; история Elo — реконструкция (или накопленные снимки при работе с API).
* Видео-рендер хайлайтов и Telegram-бот не разрабатывались (по приоритетам задачи); хайлайты — события с тиком.
* Радар-карта позиций убийств не реализована (координаты убийств уже сохраняются в анализе).
